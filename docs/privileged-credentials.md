# Privileged and cloud route boundaries

The installed OpenCode V2 SDK exposes an active `ConnectionInfo` and resolves a selected `credential` connection to either `{type:"key", key, metadata?, configuration?}` or `{type:"oauth", access, refresh, expires, methodID, metadata?}`. This is the SDK-wide union, **not** evidence that every listed integration offers both methods or that its key has billing access. The plugin checks the exact active connection ID and method before using a credential. OpenCode's SDK does not expose an AWS profile or Google Application Default Credentials (ADC) as a resolved `Credential.Value`. No adapter in this table has fixture-backed implementation; see [route triage](route-triage.json). Sources are pinned in [parity.json](parity.json) and [upstream.json](../upstream.json).

| Route | OpenCode integration and available shape | Additional selected identity/permission needed | Disposition |
|---|---|---|---|
| `openai:admin-api` | `openai` selected key (SDK also permits OAuth generally); ordinary model key is insufficient | Organization Admin key and organization ID, permission for organization usage/cost endpoint | Privileged key could be selected explicitly; not inferred from inference key. |
| `openai:legacy-credit-grants` | `openai` selected key | Legacy billing grants endpoint authorization and billing organization identity; availability can differ from the Admin API | Separate legacy entitlement; no inferred balance. |
| `claude:admin-api` | `anthropic` selected key | Anthropic Admin key and organization identity; ordinary Anthropic model key or Claude Code login is insufficient | Admin usage/cost only after a distinct authorized key is explicitly selected. |
| `vertexai:google-adc-monitoring` | `google-vertex` integration may use ambient Google ADC; resolved key/OAuth schema does not represent the ADC chain | Explicit Google Cloud project, quota metric and Cloud Monitoring read permission on that project | Requires a bounded ADC/platform adapter; no ambient credentials read in tests. |
| `openrouter:management-activity` | `openrouter` selected key covers current key balance/cap; management activity uses another authority | Explicit management key/account and activity permission; 30-day activity is separate from key spend | Do not pass inference key to management route without verified scope. |
| `bedrock:aws-cost-explorer` | `amazon-bedrock` runtime can use AWS credential chain; SDK resolved `Credential.Value` is not an AWS session | Explicit AWS account/profile/region, Cost Explorer read permissions and billing visibility | Separate platform adapter required; account spend is not an inference quota. |
| `bedrock:cloudwatch` | Same AWS platform boundary | Explicit account/profile/region, CloudWatch metric read and model/region dimension selection | Activity metric is not a quota denominator. |
| `groq:enterprise-prometheus` | `groq` selected key | Enterprise API entitlement and organization scope | Ordinary inference key permission unproven; browser-console session is separate. |
| `zenmux:api` | `zenmux` selected key | Management key/account scope for quota and PAYG balance | An inference key is not management authorization. |
| `aiand:request-logs` | `aiand` selected key | Organization key and organization ID/scope, request-log read permission; pagination may cap 30-day spend | Needs account-bound organization credentials; partial totals must be labeled partial. |
| `xai:management-api` | `xai` selected key | Management key and team ID; team billing authorization | Separate from model inference and consumer Grok account; no implied pool sharing. |

The six unresolved aliases remain `qwencloud`, `factory`, `antigravity`, `nous`, `replicate`, and `typesafe`. The pinned registry confirms their acquisition strategies but not an OpenCode integration with a verified shared billing pool. Public model availability or a brand match does not establish that account binding. Each alias stays `mapping-unverified` in `route-triage.json` until a provider-specific account/entitlement source proves the link; browser sessions are not imported to resolve it.
